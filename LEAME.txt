====================================================================
2. RESUMEN TECNICO DEL PROYECTO
====================================================================
Este proyecto consiste en una aplicación Java conectada a Oracle Database para gestionar:
- usuarios,
- pacientes,
- médicos,
- medicamentos,
- recetas,
- dispensaciones,
- anulación de dispensaciones,
- trazabilidad por medio de bitácora y movimientos de inventario.

La lógica principal del negocio se ejecuta en Oracle mediante:
- tablas,
- constraints,
- vistas,
- funciones,
- procedimientos almacenados,
- paquetes,
- triggers,
- cursores.

La aplicación Java se conecta por JDBC y consume procedimientos almacenados.

====================================================================
3. PROGRAMAS NECESARIOS Y VERSIONES
====================================================================
A continuación se indican los programas requeridos para ejecutar exactamente este proyecto.

3.1. ORACLE DATABASE 
- Programa requerido: Oracle Database 19c
- Uso en el proyecto: motor de base de datos principal
- Observación: el proyecto fue preparado para trabajar con un servicio local Oracle y un
  usuario llamado FARMA.

3.2. ORACLE SQL DEVELOPER
- Programa requerido: Oracle SQL Developer
- Uso en el proyecto: ejecutar scripts SQL/PLSQL, revisar tablas, procedimientos,
  paquetes, triggers, vistas y datos.

3.3. APACHE NETBEANS
- Version usada en el proyecto: Apache NetBeans 29
- Uso en el proyecto: abrir, compilar y ejecutar la aplicación Java.

3.4. JDK de Java
- Version requerida por el proyecto: JDK 25
- Observación importante: aunque la aplicación podría adaptarse a otra versión de Java,
  para ejecutar exactamente el proyecto entregado, lo correcto es usar JDK 25.

3.5. Maven
- Tipo de proyecto: Maven

3.6. Driver JDBC de Oracle
- Dependencia declarada en el proyecto:
  com.oracle.database.jdbc:ojdbc11:23.4.0.24.05
- Importante: en la primera compilación, Maven puede requerir conexión a Internet para
  descargar esta dependencia si no se encuentra ya en la caché local del equipo.

4. DATOS DE CONEXION QUE USA EL PROYECTO JAVA
====================================================================
La aplicación Java viene configurada con los siguientes datos:
src/main/java/com/mycompany/farma/grupo_02/conexion/ConexionOracle.java

- Clave Oracle: Farma123

Esto significa que, para que el proyecto funcione sin modificar código, el profesor debe
contar con:
- Oracle ejecutándose en la máquina local,
- listener en el puerto 1521,
- servicio Oracle llamado ORCL,
- usuario FARMA con clave Farma123.

Si el profesor tiene una instalación Oracle 19c cuyo servicio no se llama ORCL, deberá
hacer UNA de estas dos cosas:

OPCION A (recomendada para correr el proyecto sin tocar código):
- crear/usar una base o servicio llamado ORCL.

OPCION B:
- editar el archivo ConexionOracle.java y cambiar la URL por el servicio real del equipo,
  por ejemplo XEPDB1, ORCLPDB, etc.
- después de eso, guardar, limpiar y volver a ejecutar el proyecto.

18. POSIBLES ERRORES Y COMO RESOLVERLOS
====================================================================
CASO 01. Error de conexión a Oracle desde Java
Causas posibles:
- Oracle no está iniciado,
- listener apagado,
- servicio distinto de ORCL,
- usuario FARMA no existe,
- clave incorrecta.

Solución:
- iniciar Oracle,
- revisar listener,
- confirmar servicio,
- validar la URL en ConexionOracle.java,
- probar la conexión primero desde SQL Developer.

CASO 02. Maven no descarga dependencias
Causas posibles:
- sin Internet,
- proxy institucional,
- repositorio Maven bloqueado.

Solución:
- conectar a Internet,
- reintentar desde NetBeans,
- revisar configuración Maven del equipo.

CASO 03. Error por versión de Java
Causa:
- se intenta compilar con una versión distinta a JDK 25.

Solución:
- instalar y configurar JDK 25 en NetBeans.

CASO 04. Error al ejecutar scripts PL/SQL
Causa:
- ejecución por Ctrl+Enter en lugar de F5,
- el usuario no tiene los privilegios necesarios,
- los scripts se ejecutaron fuera de orden.

Solución:
- usar Run Script (F5),
- asegurarse de ejecutar 00 con SYSDBA,
- ejecutar los scripts en el orden indicado en esta guía.

CASO 05. Error por objetos ya existentes
Causa:
- se está intentando reinstalar sobre un esquema que ya tenía objetos cargados.

Solución:
- usar una instalación limpia,
- o eliminar previamente los objetos del esquema FARMA,
- o recrear el usuario FARMA desde cero.
